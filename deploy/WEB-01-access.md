# WEB-01 local access candidate

The public entry point remains the existing Cloudflare Sites Worker and its D1 binding. `dashboard/build/sites-worker.ts` checks every public request before Vinext dispatch. Public traffic requires an exact HTTPS `VIEWER_ORIGIN`, a SHA-256 hash of a high-entropy 32-byte viewer credential (entered as 64 hexadecimal characters), an independent HMAC session secret (32+ characters), and a single configured 24-hex owner scope. Missing or malformed configuration fails closed. Never place credentials in URLs, public variables, logs, or source control. CUT-01 must prove that the D1 dataset contains only that configured owner and that every public hostname reaches this Worker guard, with no direct origin route that bypasses it; the local candidate cannot establish either fact.

Open `/viewer/login`, submit the credential in a bounded form POST, and receive a 10-minute `__Host-vt_viewer` Secure/HttpOnly/SameSite=Strict cookie. The session includes only owner, issue/expiry, and a fingerprint of the configured credential hash. Credential rotation invalidates current cookies. Login attempts are limited to five per IP/minute and the gateway has a 1024-entry bounded per-isolate limiter. This is defense in depth, not a globally coordinated Cloudflare rate limit.

The public edge permits only GET `/`, approved static assets, and the exact state/PnL/orders/observability stream reads after session validation. `/api/accounts` and `/api/ingest` are rejected before Vinext for every public method and credential. All API reads are owner-scoped to the one configured D1 owner and use fixed projections; this is not multi-tenant authorization. Timefolio monitoring remains read-only. Sessions, pages, APIs, and streams are non-cacheable. Event streams close within 60 seconds or on session expiry and reconnects require a valid session.

Private ingest/account operations are available only through the named `PrivateDashboardService` entrypoint, with an independent `X-Private-Service-Authorization` bearer secret and, for ingest, the existing ingest bearer. Public fetch does not dispatch to this entrypoint. The bridge is deliberately unchanged. Its current HTTPS Sites bypass plus ingest bearer does not by itself prove a route to the named entrypoint. Therefore private bridge connectivity, envelope response compatibility, Worker service-binding configuration, hostname/TLS, and the approved CUT-01 proof remain deployment blockers. Do not repoint the bridge to the public viewer host, disable the current private route, or claim production readiness until a trusted private gateway binding is wired and verified.

The checked-in env file is a redacted template and must fail preflight until configured. Local shape fixtures are covered by `python3 -m unittest discover -s tests/refactoring -p test_web01_preflight.py`. Worker guard behavior is covered by `node --experimental-strip-types --test dashboard/scripts/test-web-access.mjs`. These checks do not prove TLS, a Cloudflare binding, secret entropy, DNS, or external reachability. Production preflight requires Worker secret metadata plus approved CUT-01 references for the single-owner D1 scope, private service binding, DNS, TLS, and certificate renewal. External checks and cutover are outside this local candidate.
