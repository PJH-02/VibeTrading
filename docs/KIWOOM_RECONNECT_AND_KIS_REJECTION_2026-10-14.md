## 키움

12:31:43 KST 로그의 최초 예외는 aiohttp WebSocket 수신의 `EofStream`이다. 이어 aiohttp가 종료 프레임을 쓰는 과정에서 이미 닫히는 소켓에 접근해 `ClientConnectionResetError: Cannot write to closing transport`가 기록됐다. 서버가 연결을 닫았거나 중간 네트워크 연결이 종료된 상황이며, 이 로그만으로 상대 서버의 종료 이유나 네트워크 위치까지 확정할 수 없다. 로그인 거절이나 NATS 타임아웃을 나타내는 오류는 아니다.

기존 수집기 supervisor는 재연결 자체를 수행했다. 그러나 일시적 오류 판정은 주로 문자열 `connection reset`에 의존했고, 붙여 쓴 클래스 이름 `ClientConnectionResetError`와 메시지 `Cannot write to closing transport`는 여기에 일치하지 않았다. 따라서 `transient=False`, 실패 1회, 장애 시간 0초에도 오류 알림이 발생했다. 오류를 전송하면서 시작 알림 상태를 초기화했으므로 복구 뒤 `[COLLECTOR START]`도 이어졌다.

수정:

- aiohttp 연결 예외와 Python ConnectionError 계열을 예외 타입으로 판정한다. 인증서/SSL 오류는 이 분류에서 제외한다.
- 키움 WebSocket의 CLOSE/CLOSING/CLOSED/ERROR를 명시적으로 처리해 supervisor가 재연결하도록 한다.
- 정상 종료 및 연결 단절은 자동 복구한다. 같은 장애의 연속 실패 5회 또는 장애 지속 90초 이상은 기존 지속 장애 알림 기준을 적용한다.
- 프로토콜·정책 거절 코드 1002/1003/1007/1008/1009/1010은 즉시 확인할 오류로 유지한다. 실제 인증·구독 거절까지 숨기지 않는다.
- 중단 구간은 기존 CollectionGapLedger에 기록되며, 분봉 폴링은 재접속 후 현재 거래일의 완료 분봉을 다시 조회한다. 재연결이 모든 과거 체결·호가 틱을 복구한다는 뜻은 아니다.

외부 연결 종료 자체를 없앴다고 주장하지 않는다. 이번 변경은 연결 종료 감지·재연결·알림 분류를 바로잡은 것이다.

따라서 관측된 거절은 클라이언트의 접속 실패·잔고 조회 실패·공매도 요청에 따른 것이 아니라 KIS 모의 주문 서버의 종목 매매허용 검증 단계에서 발생한 것으로 판단한다. 계좌의 상품 거래 약정/권한 제한인지, 모의 서버의 개별 종목 제한/상태인지까지는 공개 응답만으로 확정할 수 없다. 매수가능수량 조회는 상품 거래허용 검증을 대체하지 않는다.

[공식 모의투자 안내](https://vts3.koreainvestment.com/vts/)의 공개 스크립트는 ETF를 투자대상에 포함한다. 그러므로 KIS 모의투자에서 모든 ETF가 금지된다고 일반화하지 않는다. 현재 사용 계좌의 122630/251340 매매허용 여부는 KIS 측에서 확인할 대상이다. 사용자 요청에 따라 계좌 설정 변경·초기화·실계좌 전환이나 검증용 매수는 수행하지 않았다. 거절은 기존 알림과 장부에 명시적으로 남고 체결로 처리되지 않는다.

## 개장 알림 및 검증
