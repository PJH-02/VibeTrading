## 범위와 해석

운영 중인 Binance·Arcus·GRVT BTC/ETH/SOL의 기존 수집기, 정규화, BufferedMarketEventBus, JetStream durable ACK, Core NATS live 전송을 그대로 통과시켰다. Binance/Arcus는 대략 5건당 1건, GRVT는 전수 계측했다. 초기 snapshot은 집계에서 제외한다.

현재 운영 중인 코인 전략이 없으므로 의도 생성 단계는 실제 전략 계산 대신 측정용 즉시 주문 의도 생성이다. 지표 계산·리스크 검증·운영 전략의 주문 대기열 비용을 검증한 결과로 해석하면 안 된다. 실제 제출한 35건도 이 측정용 의도에서 생성했다.

GRVT의 실제 주문 경로는 **운영 시장 데이터 트리거 → 현재 서버 처리 → testnet 호가/서명/주문 → testnet 상태·체결 통보**이다. 운영 거래소에서의 실거래 지연이나 testnet 시세만 사용한 전체 경로를 의미하지 않는다. Binance·Arcus에는 주문을 제출하지 않았다.

WS 수신 시점은 Python websockets.recv() 반환 직후이며 NIC·커널 수신 시점이 아니다. 따라서 exchange→WS 수신에는 거래소 배치, 통신, WebSocket 내부 큐와 서버 스케줄링도 포함될 수 있다. 서버 NTP는 synchronized였지만 거래소 시계를 별도 보정하지 않아 이 구간과 이벤트 기점 E2E는 관측된 이벤트 나이이다. 서버 내부 구간은 공통 monotonic clock으로 계산했다.

추가 계측·구독자·샘플 의도 생성의 오버헤드가 포함된 짧은 표본이다. 세 수집기를 잠시 재연결했으며 초기 회복 구간도 포함한다. 해당 시점 서버의 부하 및 다른 작업의 영향도 포함하며, 보장 지연/SLA가 아니다. 단계별 분위수를 더해 전체 분위수를 만들지 않았다.

## GRVT testnet 실제 주문

BTC·ETH·SOL 각 5회씩 post-only 지정가를 등록하고 취소했다. 추가로 각 3회씩 IOC 진입·청산을 수행했다. maker 2건이 취소 전에 체결되어 해당 수량도 reduce-only IOC로 청산했다. 총 35건 = maker 15건 + IOC 20건, 체결 주문 22건 = maker 2건 + IOC 20건. 각 주문은 최소 수량/최소 명목을 충족하는 소액이며 600 USDT 미만으로 제한했다.

IOC는 시세 이동에 따른 미체결을 줄이기 위해 testnet 최우선 호가에서 최대 20 bps 범위를 허용한 지정가였다. 사전 연결·인증·계약 명세 조회 및 RPC 연결을 완료한 상태에서 측정했다. TCP/TLS/인증 초기 연결 비용은 주문 제출 구간에 포함하지 않는다. 매 주문의 서명과 증적 저장 fsync 비용은 포함한다.

제출 응답(ACK), private OPEN/FILLED 반영, 공개 호가, 실제 체결은 서로 다른 관측치이다. 공개 호가 반영은 해당 가격의 합산 수량 변화로 매칭했으므로 고유 주문 ID의 확정 통보가 아니며, 참고용이다. 주문 상태는 private 주문 ID로 매칭했다. 체결 구간은 첫 체결 통보를 기준으로 하며, 최종 20건 IOC 모두 전량 체결을 조회로 확인했다.

## 관측된 지연과 종료 확인

정규화 중앙값은 0.081~0.177ms, live 도착 후 측정용 의도 생성은 0.045~0.052ms였다. 서버 내 지연은 주로 정규화 이후 버퍼·NATS·구독자 전달에 존재했다. 이 구간 중앙값은 Binance 7.518ms, Arcus 20.740ms, GRVT 3.780ms였다. JetStream publish 함수 중앙값 자체는 각각 1.170/0.766/1.620ms였다. 현재 표본만으로 모든 지연을 NATS 서버에 귀속시킬 수는 없다.

이벤트 시각→수신은 Binance p99 873.504ms, Arcus 체결 p99 3132.155ms로 긴 꼬리가 관측되었다. 거래소 배치/시계 오차/네트워크/서버 backlog를 분리하지 않은 수치다. GRVT 최종 실행은 p50 24.699ms였지만, 앞선 짧은 시도에서는 p50 115.148ms였으므로 단일 시점의 숫자가 항상 유지된다고 가정하면 안 된다.

최종 수집기 설정은 실행 전 서비스 JSON과 정확히 일치한다: True. 세 수집기의 임시 PYTHONPATH trace mount와 LATENCY_AUDIT_ID는 제거했으며, 최종 2026-10-14T23:43:48.484+09:00에 모두 Docker healthy/phase publishing, publish 실패 0, BTC/ETH/SOL 최신 수신을 확인했다.

측정 종료 루틴에서 이미 terminal인 과거 주문의 재조회 중 RPC 거절이 1회 발생하여 원본 result.json에는 cleanup_error가 남아 있다. 이후 별도 인증 연결로 두 번 계좌를 조회해 포지션 [], 미체결 0건임을 확인했다. 숫자를 숨기거나 원본 결과를 덮어쓰지 않았다. 재사용 측정기의 종료 루틴은 terminal 주문 재조회를 생략하도록 보완했다.

준비 시도 1은 testnet 호가 freshness 조건에서 중단했고 maker 8건을 취소한 후 잔여 0을 확인했다. 준비 시도 2는 최우선 호가 지정가 IOC 청산이 IOC_CANCEL되어 신규 진입을 중단하고 reduce-only 청산했으며 잔여 0을 확인했다. 최종 시도에서 IOC 허용 범위를 20 bps로 넓혀 3종목 반복 체결 측정을 완료했다. 준비 시도의 숫자는 최종 표본과 섞지 않았다.

GRVT testnet 인증은 서버 런타임 /etc/vibetrading/app.env의 키로 성공했다. /root/vibetrading/.env의 다른 testnet 키는 인증이 거절되었다. 자격증명이나 운영 주문 설정을 변경하지 않았으며, submit 활성화는 임시 testnet 측정 프로세스에만 적용했다.
